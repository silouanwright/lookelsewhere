# Competition Delivery Plan

## Rules baseline

Reverified on 2026-08-22: eligible plugins must be submitted to the Omarchy
Plugin Marketplace before Monday, 2026-08-24 at 09:00 CEST. The Core Team
selects a three-place podium; prizes are $2,500, $1,000, and $500. A winner
must be able to receive payment through Zelle, Venmo, PayPal, or EU IBAN.
Recheck the [official announcement](https://omarchy.org/news/2026/08/the-first-plugin-competition/)
immediately before submission.

## Submission definition of done

- Public GitHub repository at `silouanwright/look-elsewhere`
- Root `manifest.json` accepted by the installed validator
- Public-quality README and MIT license
- One-command installation with no installer hook or privilege escalation
- Safe disable/removal and no orphaned background process
- Representative `preview.png`
- Short deterministic demonstration capture
- Marketplace issue/form metadata prepared and submitted
- Current commit tested on the installed Omarchy release
- Owner confirms one supported prize-payment method

## Judging story

Lead with the visible product experience, then explain technical depth:

1. Native bar presence
2. Smart Context preventing a bad interruption
3. Explainable cooldown/natural pause
4. Progressive warning and final chip
5. Calm multi-monitor break
6. Local/private architecture and recovery

Avoid leading with settings, health claims, implementation language, or a long feature list.

## Scope defense

Protected quality areas:

- State correctness and recovery
- Warning/overlay interaction polish
- Keyboard accessibility
- Theme, scaling, and multi-monitor behavior
- Privacy and transparent detector states
- Demo reliability, documentation, and install experience

Cut before compromising those:

- Long-break cadence
- History visualization beyond small aggregates
- Advanced detector thresholds UI
- Extra routine content
- Screen-sharing detection if unreliable
- Settings-window embellishment
- Sounds beyond one optional cue

## External actions

Creating the public GitHub repository, pushing commits, and submitting to the marketplace are external mutations. They require authorization if not already explicit at execution time and usable credentials in the environment.
